# TopoProof task and decision list

This file records unfinished work that must remain visible in the repository.
Entries use one of the following categories:

- **FIXME**: known defect or incomplete behaviour that can invalidate a claim.
- **IMPROVE**: worthwhile improvement that does not invalidate current behaviour.
- **DESIGN**: architectural work requiring an explicit design decision.
- **PROOF**: missing, incomplete, or insufficiently auditable proof work.
- **DOC**: missing or inconsistent executable or design documentation.
- **TOOLING**: build, packaging, CI, or developer-experience work.

Each entry has a stable identifier, a status, and an acceptance criterion. Completed
entries are removed from this file and recorded in `CHANGELOG.md` or the relevant
design decision.

## Open

### TDL-DESIGN-003: implement TopoScript embedded scripting

- **Category:** DESIGN
- **Status:** open
- **Context:** bbt scenarios invoke `topocli` with increasingly long command lines.
  Milestone 6 of the development plan introduces TopoScript, a lightweight Ada
  scripting form executed by HAC, for readable scenario inputs and the future
  language for user macros and extensions.
- **Decision required:** the arbitration questions of `DD-003` (bbt step wording,
  HAC input mode, supported language subset, line-number mapping, canonical `Put`
  representations, drawing primitives, versioning, restricted capabilities).
- **Acceptance:** the completion criteria of Milestone 6 hold, and
  `docs/features/toposcript.md` is registered in the `make test` scenario list once
  its scenarios are executable.
