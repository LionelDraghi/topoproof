# Translation

`translate` applies an exact displacement to a point: `topoproof translate X Y Z DX DY DZ`.
The canonical result is `point X Y Z`.

The diagram shows the geometry of the first scenario below: point `P`, the
translation vector `D`, and the resulting point `Q = Translate (P, D)` with
the coordinates of the test inputs and outputs. The image is generated by
`make doc` from a scene source embedded as an invisible comment in this page.

## Scenario: translate command-line values
- When I run `../bin/topoproof translate 10 -20 30 5 7 -9`
- Then the output is `point 15 -13 21`
- And there is no error

## Scenario: reject an unrepresentable result
- When I run `../bin/topoproof translate 1_000_000_000 0 0 1 0 0`
- Then the output is `error: translation is not representable`
- And there is an error

## Scenario: write the result to a file
- Given there is no file `translation.out`
- When I successfully run `../bin/topoproof translate 1 2 3 4 5 6 --output translation.out`
- Then the `translation.out` file contains `point 5 7 9`

## Proved property

`Translate (A, Displacement (A, B)) = B` is proved by SPARK over the whole
grid domain by the ghost procedure `Translations.Lemma_Translate_Displacement`.
The composed translation is always representable, for any two points of the
model.

## Scenario: translation and displacement compose to the identity
- When I run `../bin/topoproof displacement 10 -20 30 15 -13 21`
- Then the output is `vector 5 7 -9`
- When I run `../bin/topoproof translate 10 -20 30 5 7 -9`
- Then the output is `point 15 -13 21`
- And there is no error
