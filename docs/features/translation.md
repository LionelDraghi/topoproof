# Translation

`translate` applies an exact displacement to a point:
`topocli translate P=(X, Y, Z) D=(DX, DY, DZ)`.
The canonical result is `point X Y Z`.

The diagram of each scenario is generated by the command itself, with
`--draw`: the drawn `P`, `Q = Translate (P, D)` and the translation vector
are the tested values.

## Scenario: translate command-line values
- When I successfully run `../bin/topocli translate P=(10, -20, 30) D=(5, 7, -9) --draw ../docs/features/images/translation_1.svg`
- Then the output is `point 15 -13 21`

## Scenario: reject an unrepresentable result

The point starts on the corner of the grid; the translation would move it
one unit beyond the largest representable position.

![Translation beyond the grid corner](images/translation_2.svg)

- When I run `../bin/topocli translate P=(1073741823, 0, 0) D=(1, 0, 0) --draw ../docs/features/images/translation_2.svg`
- Then the output is `error: translation is not representable`
- And there is an error

## Scenario: write the result to a file
- Given there is no file `translation.out`
- When I successfully run `../bin/topocli translate P=(1, 2, 3) D=(4, 5, 6) --output translation.out`
- Then the `translation.out` file contains `point 5 7 9`

## Proved property

`Translate (A, Displacement (A, B)) = B` is proved by SPARK over the whole
grid domain by the ghost procedure `Translations.Lemma_Translate_Displacement`.
The composed translation is always representable, for any two points of the
model.

## Scenario: translation and displacement compose to the identity

The geometry of the first scenario: from `P` to `Q` and back.

![Translation diagram](images/translation_1.svg)

- When I successfully run `../bin/topocli displacement A=(10, -20, 30) B=(15, -13, 21)`
- Then the output is `vector 5 7 -9`
- When I successfully run `../bin/topocli translate P=(10, -20, 30) D=(5, 7, -9) --draw ../docs/features/images/translation_1.svg`
- Then the output is `point 15 -13 21`
